# Database Schema Management

This project uses a schema-first approach where `schema.sql` is the source of truth for the database schema. Migrations are auto-generated by diffing against the current database state.

## Why Schema-First?

This approach enables advanced PostgreSQL features like Row-Level Security (RLS) that aren't well-supported by Prisma's migration system, so that we can build safe LLM access to the database in the future.

## Workflow

### Making Schema Changes

1. **Edit `schema.sql`** directly with your changes (add columns, tables, constraints, etc.)

2. **Generate the migration:**
   ```bash
   cd apps/api
   pnpm schema:generate <migration_name>
   ```
   This will:
   - Apply all existing migrations to a temp database
   - Diff the temp database against `schema.sql`
   - Generate a new migration file if there are differences

3. **Review the generated migration** in `src/db/migrations/<timestamp>_<migration_name>.sql`
   - Edit if needed (e.g., add data migrations, backfills)

4. **Apply the migration:**
   ```bash
   pnpm schema:migrate
   ```
   This will:
   - Apply any pending migrations to your local database
   - Regenerate Prisma schema from the database
   - Regenerate Kysely types

### Example: Adding a Column

1. Edit `schema.sql`:
   ```sql
   CREATE TABLE public.pipeline_output (
       ...
       config_version integer DEFAULT 1 NOT NULL,  -- Add new column
       ...
   );
   ```

2. Generate migration:
   ```bash
   pnpm schema:generate add_config_version
   ```

3. Review and optionally add a backfill to the generated migration:
   ```sql
   -- Auto-generated
   ALTER TABLE public.pipeline_output ADD COLUMN config_version integer DEFAULT 1 NOT NULL;
   
   -- Manual addition: backfill existing rows
   UPDATE pipeline_output SET config_version = 1 WHERE config_version IS NULL;
   ```

4. Apply:
   ```bash
   pnpm schema:migrate
   ```

## Files

- `schema.sql` - Source of truth for the database schema
- `migrations/` - Migration files (applied in alphabetical order)
- `migrations/init.sql` - Initial migration that sets up the migration tracking table
- `generate.sh` - Script that generates migrations by diffing against schema.sql
- `migrate.sh` - Script that applies pending migrations

## Notes

- Migrations are tracked in the `_migrations.migrations` table
- The Prisma schema is auto-generated from the database (not the other way around)
- Kysely types are regenerated after each migration
