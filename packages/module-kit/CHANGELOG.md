## 0.14.0

### Minor Changes

- c7004f6: A poll's answer may say when the edge is next worth polling (`PollEdgeAnswer.pollAgainAt`, an ISO instant; adapter protocol 2.7): a host speaking 2.7 polls it then when that is sooner than its interval, never sooner than a second on. It is a host behaviour, so a module that answers it states no minor: an older host ignores the member and polls on its interval.

### Patch Changes

- 4516899: Each module says who acted where it builds an arrival (adapter protocol 2.7 `actor`): who posted, reacted or pressed in Slack, a Granola meeting's owner, a mail's sender, a Telegram or WhatsApp sender, the Attio member who made a change. A run reads `@actor_*` from it; `extractActor` and `getActorCandidates` read it from the run's trigger (`event.arrival.actor`), Slack still resolving the member's email through `users.info` and email still adding its forwarding relays. `module-kit` gains `firedActor(event)`.
- 4bb86df: `firedRecordFields(event)`: the fields of the record that landed on the arrival a run was fired on, as its module put them on the landing; none for a run no arrival fired. A module's `extractActor` and `getActorCandidates` read the actor from these, since no 0.13 run's event carries a `payload`.

## 0.13.0

### Minor Changes

- faa7050: A module's `ensureEventSubscription`, `removeEventSubscription` and `refreshEventSubscription` are typed by both shapes of adapter protocol 2.6: a listen's in the settings form (`events`, unchanged), or a subscription for the arrivals on one listenable edge pushed to the connection or per scope (`EnsureEdgeSubscriptionInput`: `{ edge, filter?, scope?, callbackUrl, current? }`, and `RemoveEdgeSubscriptionInput`, `RefreshEdgeSubscriptionInput` naming the same `edge`, `filter` and `scope`), told apart by `edge`. A host makes one for every listen on the same connection, edge, filter and scope. Set `takenApplied: true` on an arrival you deliver only when you applied `filter` to it.
- acec0bd: A replayed request (`listen-fire listens replay`) reaches a module that checks its own requests with `replayed: true` (adapter protocol 2.6), read by module-kit's `inboundRequest` from the host's call alone, never from a header, the query or the body. `@lf/stripe`, `@lf/webhook`, `@lf/whatsapp` and `@lf/email` skip their signature and timestamp checks for it. A kept request holds only the headers a module names in `inbound.captureHeaders`, never a signature: `@lf/email` names `svix-id` (which tells a Resend notification from a Mailgun post), `@lf/forms` names `content-type`; the others need none (docs/contracts/adapter-protocol.md).
- c4af6cc: A module states how a listen learns a hop's members changed in one member, `membersChange: "pushed" | { relistEverySeconds }`, where it stated `cheapToList` with `parentChanges` or `relistEverySeconds`. A field of kind `owned` may declare `format` (`cron` or `timeZone`), and the checker validates a literal by that format alone, never by the scalar's name. A field may declare `changedIn: { release, note }`, so a check for an upgrade from before that release warns where a program reads it. A `listenSettingsBecome` mapping may declare `changed` (the rewrite hears otherwise, said and never applied safely) and `alsoArrivesOn` (its events arrive on more edges: no rewrite), and a key's `values` may spell a value `null` (it narrowed nothing).
- 46efd84: `ctx.records`: the host's records door, facts about its own runs and waits (docs/contracts/system-events.md), read as `ctx.records.read(method, params)`. serve-module reaches it at `LF_HOST_URL` under `LF_HOST_TOKEN`, as it reaches the models and OCR doors (`hostRecords`); a host that serves none refuses a read by name (`refusingRecords`, the in-process default).
- 16e3776: A module's inbound declaration may name `redactFields`: the body and query fields that may carry a credential, dropped before a request is kept (a JSON body's own members, a form's fields and the members of a JSON object a form field holds, and the query's parameters). A body that names none is kept byte for byte. `@lf/slack` names its legacy verification `token`. A header whose name holds `token`, `key`, `auth`, `hmac` or `password` is never kept.
- 16e3776: A module's `poll` takes an edge's input alone (`PollEdgeInput`) and answers its arrivals (`PollEdgeAnswer`); `PollInput` and `PollAnswer` are gone from the kit, and a 0.12 settings poll's input reaches no module. Dealroom, Evertrace, GitHub, Gmail, Granola and System no longer refuse that input themselves. The in-process `Adapter.ensureEventSubscription` takes an edge's subscription; removing and refreshing one still take a 0.12 settings listen's webhook, so a host can remove it.
- da1a05b: `takenComparisons(filter)` reads the part of a listen's WHERE a polled module takes (adapter protocol 2.6's `filter`) as comparisons, `narrowedTo` names the texts an `==` or `IN` narrows to, and `holds` judges a field as the engine does, so a module can apply what its provider cannot and say `takenApplied: true`.
  
  An OR of `CONTAINS` on one field (a field declaring `containsAny`) reads as a `containsAny` comparison, which `holds` judges as any of its values contained.
- ad23b9c: A module's `poll` is a poll of a listenable edge (`PollEdgeInput`: `{ edge, filter?, scope?, cursor? }` → `PollEdgeAnswer`: `{ arrivals, cursor? }`). A host polls an edge once for every listen on the same connection, edge, filter and scope. Set `takenApplied: true` on an arrival only when the module applied `filter` to it; otherwise the host checks the whole filter itself. An entry point may declare its root collection's `capability`.

### Patch Changes

- 4c09d6a: Airtable refusing a credential fails the call at once, where before every failure was retried as if transient, for over two minutes, saying nothing (`listen-fire check` with a placeholder token hung). A 401 is refreshed once where the host can, then answered as `credential_refused`, naming what Airtable said. Any other status no retry can change (a 403, a 404, a 422) fails at once, naming the status. Only a 429, a 5xx or a network error is sent again, through module-kit's shared `retryingFetch`: at most 5 attempts within 45 s of waiting, a 429 waiting Airtable's documented 30 s penalty, and then a failure naming the status, the attempts and the wait.
  
  module-kit: `CredentialRefusedError`, thrown by a module served through the kit, answers the protocol's `credential_refused` (not retryable), on which the calling host refreshes the credential and retries the call once. `retryingFetch` takes `rateLimitWaitMs`, the wait before retrying a 429 that names no Retry-After.
- 301dab3: An arrival a module reports may carry `occurredAt` (adapter protocol 2.6), when the change happened at its provider, as an ISO 8601 instant. listen-fire's loop breaker measures from it whether a run's write caused the arrival, so an echo a poll finds late is still the write's. Send it wherever your system stamps a time; one that is not an instant is refused, naming the arrival's place and edge.
- 3c2774e: Adapter protocol 2.6, arrivals for listens: an arrival a module reports (beside `preprocessInbound`'s events, on `accepted(events, { arrivals })`, or at the `wake` door) may name no `key` when it lands on a root edge, and may carry `parents`, `about`, `notFor` and `takenApplied` (`Arrival` in `@listen-fire/engine-contracts`). A module that reports a root arrival states `protocolMinor: 6`.
- dd81bed: Adapter protocol 2.5, arrivals: an adapter with listenable edges offers `arrivals: { awaitKeys }`, and the kit's server lists and answers `awaitKeys` (still stating 2.0). `accepted(events, { arrivals })` reports what a checked request says landed on listenable edges; `preprocessInbound` may answer `arrivals` beside its events. An in-process module's `awaitKeys` answers are validated like its other answers.
- a942076: `holds` decides a taken comparison exactly as the engine's judge does, so a module that applies the taken part itself and says `takenApplied` never drops an arrival the host would fire: numeric texts order as numbers (`"100" > "20"`, `"5" > 3`), dates are ISO texts only and one with no offset is UTC (`"Mar 5, 2024"` orders as text), lists are equal as sets of their distinct members, `== null` holds for an absent field and `!= null` fails for one, and `==` is strict. An OR with `== null` is no longer read as an `IN` list: `takenComparisons` leaves it to the host. Both are held to `conformance/taken-comparisons.json`, which the engine's Rust runs too.
- 9520af9: A module that checks its own inbound requests can answer a page: `reply(status, { html })`, sent as `text/html`. `accepted(events, { arrivals, reply })` names what the door answers once it has kept the request, in place of its own acknowledgement (a page saying an answer was recorded). `ctx.config.inboundUrl` is where the install's inbound requests reach the module, when the host sends it (`inbound: { url }` on the request): a module hands out links to itself with it.
- 9e9316c: The key form of awaits is gone from the kit, as from every host of release 0.13: its server no longer dispatches `resolveAwait`, an in-process module's `wakeKeys` answers are no longer validated, and `accepted(events, …)` no longer takes `wakeKeys`. Report arrivals instead (`accepted(events, { arrivals })`, adapter protocol 2.5).
- 5bfc3f2: A module's manifest may declare `listenSettingsBecome`: how its 0.12 settings listens (`listen to gh { events: ["mention"] }`) become 0.13 traversals (`listen to gh-[n:Notifications WHERE n.Reason IN ["mention"]]->`), so `listen-fire upgrade` rewrites them. module-kit serves it in the manifest as declared; the host refuses, when the module is described, a path naming an edge the module does not describe, a key mapped past the path, or a comparison naming no field.
- 66d32d5: An adapter module's manifest may declare `resendWindowSeconds`, how long its provider may re-send an arrival it already sent; module-kit states it on the wire. A module's references and entry points may declare how a listen reads them (`delivery`, `pollEverySeconds`, `bounded`, `boundedBy`, `carries`, `attributes`, `membersChange`; an entry point also `listenable`, `cursor`, `identity`, `version`), and a field may be of kind `owned`. A 0.13 `listen-fire` and `introspectAdapter` refuse a declaration that cannot mean what it says, naming it.
- abc777e: An adapter module's manifest may say `introspectedSchema: true` on the wire: its schema comes from the connected account, so describing it needs a credential. module-kit states it from the module's manifest (Airtable, Attio, Affinity and Google Sheets already declared it). `listen-fire modules show` reads it to say a module's records cannot be listed without an account.

## 0.12.10

### Patch Changes

- The command is now `listen-fire`, no longer `lf`: every message, hint, description and handbook page that tells someone what to run names `listen-fire` (for example `listen-fire connect s3_files`, `listen-fire credential add --module webhook <name>`). Module names (`@lf/…`), `lf.yaml`, `.lf/` and `LF_*` variables are unchanged.
- 93e4f6f: `retryingFetch` no longer retries a request the host refused by policy: an error carrying the code `LF_POLICY_REFUSAL` (`POLICY_REFUSAL_CODE`, `isPolicyRefusal`) is thrown at once with its own message, not retried as a network error. `@lf/mcp` benefits through its wrapped fetch.
- d0a1d12: Stripe's webhook signature check moves into module-kit (`verifyStripeSignature`, `stripeSignature`), so every module that takes Stripe's deliveries checks them one way. `@lf/webhook`'s `stripe` scheme now calls it and behaves as before: the `Stripe-Signature` header's `v1` HMAC of `<t>.<body>`, any of several `v1`s, and a signature older than five minutes refused.
  
  `@lf/webhook`'s handbook section and README point a Stripe sender to `@lf/stripe`, which types its events, objects and amounts.

## 0.12.9

### Patch Changes

- 7eb4ba0: `retryingFetch` wraps `ctx.fetch` with exponential backoff and jitter on 429, 5xx and network errors, honouring `Retry-After`, with capped attempts and total wait. ## 0.12.8

### Patch Changes

- 26d988a: An Airtable listen can fire on one field changing, and on it changing to a value: `listen to hiring { base: "app…", table: "tbl…", field: "Stage", becomes: "Interview" } fire …` runs only when a change touched `Stage` and made it `Interview` (it was not `Interview` before). The `Record Change` event names the fields a change touched (`Changed Fields`) and reaches the row as it was through an `Old Record` edge, typed like the table, so `change-[:`Old Record`]->.Stage` is the `Stage` enum. A new Airtable webhook asks for previous cell values; select cells in a delivery read as their choice's name. The engine's listen scope gate (`eventMatchesTriggerScope`) applies `field` over an event's `changedFields` and `becomes` over its payload's `fields` and `previous`.
  
  The checker holds both keys against the table the listen watches. A module declares them with two new listen config formats: `field` (one field of the watched record) and `field-value` (a value of the field the `field` key names, beside exactly one `field` key). A `field` the table lacks is refused, naming the table's fields (`MOV_LISTEN_BAD_CONFIG`); a `becomes` that is not a choice of a select field is refused with a did-you-mean (`MOV_ENUM_UNKNOWN_VALUE`), and one of the wrong type for any other field (text for a number field) is refused (`MOV_LISTEN_BAD_CONFIG`), as is a `becomes` without a `field`. Only configs that could never fire are refused. `lf` applies the same `field` and `becomes` gate as the engine.
  
  A listen config format a checker does not know no longer refuses the catalog. A newer module may declare a format an older core lacks; its key's value is then a plain, unchecked value, and the checker says so once as an Info naming the format (`MOV_LISTEN_BAD_CONFIG`, severity info). `lf`'s manifest reader and the wire schema (`WireListenDeclarations`) keep such a format rather than refusing the manifest. So a module release no longer needs the core released first.
  
  `lf serve` registers Airtable webhooks. A module may declare `subscriptionScopeKeys` in its manifest (`module-kit` states them; Airtable's are `base` and `table`): `lf` then keeps one webhook per credential and scope, the scope being a listen's config values of those keys, and sends it as `scope` on `ensureEventSubscription` and `removeEventSubscription`, as the platform does. Each scoped webhook has its own door, `/api/public/webhook-sync/<provider>/<credential>/<key>` (the key is the scope's values, `appHIRE01.tblCAND01`), its own secret and pull cursor, and is kept in the credential's `webhook_subscriptions` field. A delivery there runs only the listens of that credential and scope; adding or removing a listen on another table registers or removes only that table's webhook. A module that declares no scope keys keeps its one webhook per credential, in the same fields and at the same door as before. A delivery's events are read (`preprocessInbound`, `wakeKeys`) as the user credential its door names, so a pulled source such as Airtable can read its payload feed. The fake Airtable gains a delivery door (`POST /airtable/control/deliver`) that queues a change on every webhook of the base that takes it and pings each one signed as Airtable signs, and its changes may carry previous cell values.
  
  Under `lf`, the event's `Record` and `Old Record` edges are narrowed to the table a movement's signature names, as the platform narrows them: in `function f(change: <hiring-[:`Record Change` WHERE `table` == "tblCAND01"]->>)`, `change-[:`Old Record`]->.Stage` is the Candidates table's `Stage` enum. A listen config key may declare `narrows: { collection, matchField }` (on the wire manifest; `module-kit` states it; Airtable's `base` and `table` do): it is one hop of the address. `lf` walks the address with the module's `edgesFrom` from the connection's root (a connection's entry position consumes the hops it pins), grafts a copy of the event node per address with its edges onto the last hop's collection retargeted at the walked table, and publishes the hop values a listen may name, so a listen's unknown table id is refused with a did-you-mean.
  
  Adapter protocol 2.4: an event subscription a source lets lapse. `ensureEventSubscription` may answer `expiresAt`, and a module may list `refreshEventSubscription` (`{ externalId, scope? }` → `{ expiresAt? }`); `PROTOCOL_MINOR` is 4 in `engine-contracts` and `module-wire` (`lf` and the engine speak 2.0 to 2.4). A module's stated minor is now what it needs its host to speak: its author's declared `protocolMinor`, else 0 — `protocolMinorOf`/`protocol_minor_of`, the module-kit stamping (TypeScript and Rust) and the slot manifests no longer raise it for offered methods, so a module listing `refreshEventSubscription`, a `.watch` or `work.enqueueIfAbsent` states 0 and an older host still reads it; `minorIntroducing`/`minor_introducing` name the minor that introduced a method a host requires. `lf` keeps each webhook's expiry with its registration and queues a `refresh_subscription` work row a day before it (halfway there for a lifetime under two days), which `lf serve` runs on its tick and `lf drain` takes, the wake slot told when it is due. A refresh that fails is printed once and tried again in 15 minutes; a webhook found lapsed is removed, registered anew and its pull cursor reset; one kept with no expiry is refreshed at once to learn it. Airtable answers its webhook's `expirationTime` as `expiresAt` from registering and refreshing, and lists `refreshEventSubscription`. The fake Airtable gains a clock (`POST /airtable/control/advance-clock { ms }`): a webhook past its expiry is pinged no more and cannot be refreshed. A webhook `lf serve` replaces because its events or door changed has its pull cursor reset too.
- 1cddbb8: A module's `checkInbound` answer can carry `deliveryId` in TypeScript: `InboundCheck`'s `accepted` outcome has it, and module-kit's `accepted(events, { deliveryId })` sets it. The wire and `lf` already took it (a repeat under the same id is answered `duplicate: true` and runs nothing). Additive.
- 0215c37: `lf` describes a module once per position a program constructs it with, and sends that position on every call of the connection, so an Airtable base's tables are typed and checked under `lf`. A module's manifest may declare `positionArgs` (`module-kit` states them from the module's manifest); the fake Airtable's Companies table gains select fields with choices. The checker holds each text literal of a list written into a list of enum (an Airtable multiple select) against the enum, and a WHERE written inside a parameter's type (`<crm-[c:Companies WHERE c.Stage == "Lost"]->>`) against the enum of the field it compares, as it already did a single literal and a WHERE in a body (`MOV_ENUM_UNKNOWN_VALUE`). A listen on a positioned connection is polled in its position (the call's `settings`) under a checkpoint of its own.

## 0.12.7

### Patch Changes

- 216a7a4: A module served by `serve-module` keeps a run's read memo and call ceiling, as it does in process. Each call is answered inside the run scope its `cacheScopeId` names: the calls of one run share it, two runs never do, and a call under `<none>` or `<slot>` (a host's own reads, a slot's calls) is answered outside any run.
  
  - The protocol has no message that says a run has ended. A scope is let go after 10 minutes with no call, or when the process keeps 64 and another run arrives (the least recently used goes).
  - The run scope (the read memo and the call ceiling) moved from the engine to `@listen-fire/module-runtime`, which the kit and the engine both stand on. The engine's segment opens it around every in-process adapter call as before; its exports are unchanged.
  - Under `lf`, the Affinity module's `AFFINITY_MAX_CALLS_PER_RUN` now counts, per adapter instance per run segment, as it does in process.
  - `serve-module` says so on stderr, once at start, when the process holds more than one copy of `module-runtime`'s run scope: a module on a different copy than the kit's would silently have no run cache or call ceiling.
