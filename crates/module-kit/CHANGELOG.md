# Changelog

## Unreleased

## 0.13.0 - 2026-11-02

- Breaking: the `LoopGuard` trait loses `is_echo`, with `Echo` and `CurrentRecord`: the loop guard slot retired `guard.isEcho`, which listen-fire stopped calling in 0.13 (docs/contracts/loop-guard-slot.md). A guard built on the kit drops its `is_echo` to compile; one still serving the method over the wire is never asked.
- `UnjudgedNote` and `UnjudgedArrival` carry `adapter` (the module the arrival came from) and `landing` (what landed, `{ recordId?, recordType?, fields }`, as its module reported it). A store module built on the kit keeps both and answers them on `unjudged.list`: `@lf/system` recognises a report about one of its own `Arrival Not Judged` events by them (docs/contracts/system-events.md). Both read as none when absent.
- The `Store` trait gains `unjudged.note` (`UnjudgedNote { pipeline, arrival, file, movement, delivery_id, edge, record_id, reason, cause, at, attempt, forget_before }`, answering whether it is new) and `unjudged.list` (`UnjudgedList { after, pipeline, limit }`, answering `Vec<UnjudgedArrival>`): each listen that could not judge an arrival, once per listen, arrival and attempt (0 as delivered, one more per `listen-fire listens replay`), which listen-fire's records door reports as `Arrival Not Judged` (docs/contracts/store-slot.md); listen-fire keeps and reads none from a store that answers `method_not_implemented`.
- `NewDelivery` and `DeliveryRow` carry `request`: the request a delivery was received as (its body and query without the fields its module declares in `inbound.redactFields`, only the headers its module declares it reads, never a signature header, and the arrivals it brought; the body is otherwise as received), which `inbound.delivery` answers while the delivery is kept. It is sensitive; listen-fire shows it only when asked (`listen-fire deliveries show <id> --request`) and replays a listen through it (`listen-fire listens replay`).
- An arrival's landing and parents may name `unknown`, the fields the module could not read: a listen whose filter reads one runs nothing for it and the host reports it (adapter protocol 2.6, additive).
- `ListenResolution` gains `parents` (by edge, the ids of the records each resolved hop reported per record hangs off; serialised only when there are some, read as none when absent): a store keeps it with the heads (docs/contracts/store-slot.md).
- The `Store` trait gains what the records door reads (docs/contracts/system-events.md): `runs.failed` (`RunsFailed { after, until, limit }`), `releases.note` (`ReleasesNote { version, at }`) and `releases.list` (`ReleasesList { after, limit }`); listen-fire reads none from a store that answers `method_not_implemented`. `waits.open` takes `record_id`, and `Stranded` carries it.
- Breaking (listen-fire 0.13): the `Store` trait gains `listens.hold` (`ListensHold { pipeline }`), which adds one to a paused listen's `held` count, and `ListenState` gains `held` (`u64`): a pause (`listens.setPaused`) keeps it, a resume (`None`) clears it, a resolve keeps it.
- Breaking (listen-fire 0.13): the `Store` trait gains the write ledger, `writes.record` (`WritesRecord { adapter, record_type, external_id, run_id, depth, at, forget_before }`) and `writes.depth` (`WritesDepth { adapter, record_type, external_id, since }`, answering `Option<DeepestWrite { run_id, depth }>`): each record write a run sends, with the run's place in its chain of writes and arrivals, which listen-fire's loop breaker reads to pause a listen whose chain is too deep (docs/contracts/store-slot.md). An arrival may carry `occurredAt`, when it happened at its provider (adapter protocol 2.6).
- Breaking (listen-fire 0.13): the `Store` trait gains the members listen-fire's store client calls, so a store module built on the kit no longer compiles until it serves them. `listens.states`, `listens.claimResolve`, `listens.saveResolution` and `listens.setPaused` keep each listen's resolved heads (`ListenState`, `ListenResolution`). `waits.sweep` takes `WaitsSweep { limit, floor }` and answers `Swept { swept }`; `floor`, when given, is a mark the caller's own steps hold, and nothing above it goes either: an arrival goes once no live wait reads it and it is at or below the lowest mark an unexpired lease kept (`leases.claim` keeps `waits.mark` as it claims), else the latest seq. `waits.log` takes `resend_window_ms`: keep each identity apart from its entry for that window. `inbound.keepDelivery` takes `waits` (`DeliveryWait`, with `PreNoted`), opened from the mark before the arrivals, and `Kept` answers `arrival_mark`, that mark. `work.bury` of a `fire_event` row drops the waits opened under it for runs that never started. `DeliverySource` gains `Poll`: a poll of a listenable edge that fired a listen, kept as a delivery (docs/contracts/store-slot.md). `work.completeKey { key } -> bool` completes a row its caller queued a run lease out and ran itself, unless a live claim holds it, dropping the waits opened under it for runs that never started; `inbound.keepDelivery` refuses `waits` sent without `arrivals`.
- Adapter protocol 2.6: an arrival an adapter reports may name no `key` on a root edge, and may carry `parents`, `about`, `notFor` and `takenApplied`; an adapter that reports a root arrival states `protocolMinor: 6` (docs/contracts/adapter-protocol.md, Reporting arrivals).
- A module built on the kit declares how each listenable edge is listened to, in `Reference`'s and `EntryPoint`'s free members: `delivery`, `pollEverySeconds`, `bounded`, `boundedBy`, `carries`, `scopedBy`, `attributes`, `addressed`, `membersChange`, and on an entry point `listenable`, `cursor`, `identity` and `version`. A `Field` may be of kind `owned`, naming in `owned: { name, allowPattern? }` a scalar the module parses. A manifest may declare `resendWindowSeconds`. A 0.13 `listen-fire` refuses each, by name, where it cannot mean what it says (docs/contracts/adapter-protocol.md).
- Stranded waits (docs/contracts/stranded-waits.md): a wait parked on a record its module reports deleted stays parked and is marked stranded. `waits.log` answers `Logged { wakes, stranded }`: a gone arrival strands each wait parked on its record, and a later arrival on the record clears that and wakes them (the newest report wins). `parks.commit` and `parks.commitSegment` strand a wait they park on a record whose newest arrival after its mark is gone. `waits.open`'s `key` is optional: none is a wait on a record already gone, one per run and edge. `waits.arrivals` no longer answers `gone`. The method table serves `waits.stranded { runId?, after?, limit? }`, the stranded waits, oldest first, one run's or every run's paged. A store module built on the kit implements it (listen-fire reads none from a module that does not serve it).
- A gone arrival wakes no wait: `waits.log` answers no wait for it, and `parks.commitSegment` queues no `wake_await` for a wait whose record is gone. A wait whose record is deleted keeps waiting (listen-fire 0.13: a `race` with a `sleep` is the way out).
- `waits.log` queues, in its own write, a `wake_await` row per wait it answers (payload `{ waitId, runId, address }`, team `teamId`, due now), one per wait however many of the arrivals answer it: a store module built on the kit queues them in `log_arrivals`'s transaction, so a crash leaves both the arrivals and their wakes or neither. Its `keep_delivery` must not queue a second set when it logs a delivery's arrivals through that same `log_arrivals`: the rows the log queued are the ones it answers as `wakes`. The shared waits cases' `log` steps assert the rows queued (`queued`).
- `inbound.keepDelivery` may carry a delivery's `arrivals` (`DeliveryArrivals`), logged in the same write after the receipt: each `fire_event` row gains `arrivalMark`, the `wake_await` row `waits.log` queues per wait they answer is queued with them (once), and `Kept` answers them as `wakes`. A store module built on the kit implements it, and lists `waits.log` in its manifest (listen-fire refuses a delivery that reports arrivals to a store that does not); `NewWork` is now `Serialize`. `waits.log` skips a repeat: an arrival whose identity and version its record's edge logged within the retention.
- `WaitsNote` carries `leaf`: the address of the leaf the noting segment resumed, when it resumed one. A store module built on the kit keeps such a note when `parks.finishLeaf` finishes that leaf or `parks.commit` parks at its address, and drops it when `parks.claimLeaf` claims the leaf again (that segment died), so its arrival is read again (docs/contracts/store-slot.md).
- `WaitsNote` carries `fence`, the noting segment's run lease: a store module built on the kit refuses the note (`run_lease_lost`) when the run is not leased under it, so a segment that lost its run notes nothing.
- The store slot's method table serves `parks.commitSegment { runId, teamId, fence, resumed, joins, parks, settle, owedRaces, settledRace }`: a segment's join counts, its parks, the end of the leaf it resumed, the run's settle (`SegmentSettle`, as `runs.settle` takes it, or none), the races it owes (`OwedRace`, each queued as a `settle_race` work row) and the race it settled (its row deleted), as one fenced write, answering the `wake_await` rows it queued for the waits it parks whose arrivals are unread. A store module built on the kit implements it. listen-fire 0.13 calls it at the end of every segment that parked, recorded a join, resumed a leaf or settled a race, and fails a run whose store does not answer it. Of the other segments, one that settles its run does so with `runs.settle` alone, and one that leaves its run as it stands writes nothing (a callback's body that parked nothing, or a failed segment of a run already settled). (`ParksCommit` carries no `resumed`.)
- The store slot's method table serves `parks.owedRaces { runId }`: the run's `settle_race` rows' payloads (`OwedRace`), oldest first. listen-fire 0.13 reads it as each segment ends, and never settles a run `completed` while it owes a race. `joins.deleteFrames` drops the `settle_race` rows owed at the frames it deletes, and `leases.dropRunState` drops the run's.
- The store slot's method table serves the waits family: `waits.mark`, `waits.log`, `waits.open`, `waits.arrivals`, `waits.note` and `waits.sweep`, and `parks.commit`'s park may be `{ kind: "wait", waitId }`. A store module built on the kit implements the six new `Store` methods (docs/contracts/store-slot.md).
- `Reference`'s free members are documented as the 0.13 ones: `listenable`, `cursor`, `identity`, `version`, `readable`. A module built on the kit declares `listenable` where it declared `awaitable` and `watchable`, and drops `resolvesEmpty` (a deleted record leaves the wait waiting on every edge); a 0.13 `listen-fire` refuses the retired three.

## 0.12.8 - 2026-10-27

- The store slot's method table serves `runs.rerun { runId, input, at, fence }`, which starts a failed run's next attempt as one fenced write (`null` when the run's status is not `failed`). A run row may answer `attempt` and `attempts` (the earlier attempts, oldest first). A store module built on the kit can now serve `lf runs rerun`.

## 0.12.6 - 2026-10-25

- A module's manifest states the adapter protocol minor it uses (`protocolMinor`), computed from its features; a declared `protocolMinor` can raise it, never lower it.
- Its own version from here on.
