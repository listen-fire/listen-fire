A new module, `@lf/github`: GitHub notifications, repositories, pull requests and issues. A listen on `Notification` fires once per notification thread that is new or changed since the last poll, labelled with GitHub's reason, so `listen to gh { events: ["review_requested", "mention"] }` narrows by it and `listen-fire check` refuses a reason GitHub never sends; `participating: true` keeps threads you take part in. The first poll arms and delivers nothing. Each later poll is conditional (`If-Modified-Since`, so an unchanged feed is a 304) and never sooner than `X-Poll-Interval`. A notification walks to its `Pull Request` or `Issue`; a repository holds its `Pull Requests` and `Issues` (open and closed unless the WHERE pins `State`; state, author, labels, an assignee and an `Updated At` floor reach GitHub); each holds its `Comments` and `Labels`. Writes: a comment along `Comments`, a label along `Labels`. The credential is a personal access token (`listen-fire credential add --module github <name>`), with an optional API base URL for GitHub Enterprise Server; the notifications feed needs a classic token. This is the package's first release: `changeset version` takes it from 0.12.7 to 0.12.8.
