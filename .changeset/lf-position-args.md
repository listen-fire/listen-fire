`lf` describes a module once per position a program constructs it with, and sends that position on every call of the connection, so an Airtable base's tables are typed and checked under `lf`. A module's manifest may declare `positionArgs` (`module-kit` states them from the module's manifest); the fake Airtable's Companies table gains select fields with choices. The checker holds each text literal of a list written into a list of enum (an Airtable multiple select) against the enum, and a WHERE written inside a parameter's type (`<crm-[c:Companies WHERE c.Stage == "Lost"]->>`) against the enum of the field it compares, as it already did a single literal and a WHERE in a body (`MOV_ENUM_UNKNOWN_VALUE`).
