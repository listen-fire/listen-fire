Evertrace arrives on two listenable edges, each polled every five minutes (lf.yaml `pollEvery` overrides it for a connection) with its own cursor: `Signals`, the edge past signals are read along (``listen to evertrace-[s:Signals WHERE s.`Saved Search` == "Stealth in Europe"]-> fire f``), and `List Entries`, which lands a `List Entry` each time a signal is added to a list (``listen to evertrace-[e:`List Entries` WHERE e.`List Name` == "Pipeline"]-> fire f``). An arrival carries `occurredAt`; an entry is `about` its signal. New fields: `Saved Search` on a signal (an owned `EvertraceSavedSearch`, a saved search by title or id; the module reads the search and judges the rest of the taken filter itself, and a walk of `Signals` reads through it too, each signal carrying the search it was found by) and `List Name` (an owned `EvertraceListName`, by name or id, choosing the lists read) and `List Id` on a list entry. A signal and a list entry each have an `Id`, its identity. It declares how a 0.12 `listen to evertrace { search }` and `{ events: ["list_entry"], list }` become these (`listenSettingsBecome`, chosen by the event named; one naming both events has no rewrite) and no longer declares `listenConfig`, `fires` edges or event types. Adapter protocol 2.6.
