Evertrace arrives on two listenable edges, each polled every five minutes (lf.yaml `pollEvery` overrides it for a connection) with its own cursor: `Signals`, the edge past signals are read along (``listen to evertrace-[s:Signals WHERE s.`Saved Search` == "Stealth in Europe"]-> fire f``), and `List Entries`, which lands a `List Entry` each time a signal is added to a list (``listen to evertrace-[e:`List Entries` WHERE e.`List Name` == "Pipeline"]-> fire f``). An arrival carries `occurredAt`; an entry is `about` its signal. New fields: `Saved Search` on a signal (a saved search by title or id; the module reads the search and judges the rest of the taken filter itself) and `List Name` and `List Id` on a list entry (`List Name` by name or id chooses the lists read). It declares how a 0.12 `listen to evertrace { search }` and `{ events: ["list_entry"], list }` become these (`listenSettingsBecome`, chosen by the event named; one naming both events has no rewrite) and no longer declares `listenConfig`, `fires` edges or event types. Adapter protocol 2.6.
