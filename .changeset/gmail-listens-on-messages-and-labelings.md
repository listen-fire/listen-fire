Gmail listens on two edges, polled every minute (lf.yaml `pollEvery` overrides it for a connection). `Messages`, readable and listenable, hears each message added to the mailbox: `listen to mail-[m:Messages WHERE m.Labels CONTAINS "INBOX" AND m.Query == "from:acme"]-> fire f`. Sent mail and drafts are added too, so a listen says which labels it means. `Query` is a new field, an owned `GmailQuery` compared with `==` only: Gmail's search written as in its search box, applied at Gmail; read, it is the search a message was found by. `Labelings`, listenable only, hears each label added to a message already in the mailbox, landing a `Labeling` with its `Label`, `Label Type` (`user`, `system`) and the message's fields, and a `Message` edge to the message; `l.Label == "Deals"` takes a user label by its name. A label removed and added again is a second labeling. `Labels` takes `containsAny`: `m.Labels CONTAINS "Deals" OR m.Labels CONTAINS "Hiring"` hears mail carrying either, each user label by its name. The module applies the whole taken filter itself (`takenApplied`), names user labels as a person sees them, and carries `occurredAt` and, for a labeling, `about` its message. It declares how a 0.12 `listen to mail { query, labels, events }` becomes these (`listenSettingsBecome`, `events: ["label_added"]` choosing `Labelings`) and no longer declares `subscribableEvents`, `listenConfig`, a `fires` edge, event types or `Added Label`. Adapter protocol 2.6.
