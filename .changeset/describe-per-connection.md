`lf` describes an adapter once per connection: each credential bound to the module that the movement files import is asked `listEntryPoints` and `describe` as itself (one bound but never imported is not asked), and each connection is typed by its own answer, as the hosted product types it. Before, every connection of a module was typed by the first credential's answer, so a call another connection's schema allowed could pass `lf check`.
